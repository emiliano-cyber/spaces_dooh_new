 EL ORDEN NO ES NEGOCIABLE:
      DNS  ->  CERTIFICADO  ->  VHOST  ->  RECARGA

 Y no es manía. Dos razones, las dos hacen dano:

  · nginx NO ARRANCA si `ssl_certificate` apunta a un archivo
    que no existe. `nginx -t` falla y el reload no ocurre.
  · El HSTS del apice lleva `includeSubDomains`, que obliga a
    HTTPS a TODO subdominio de space-os.io durante DOS ANOS.
    Un subdominio nuevo sin certificado no queda "roto":
    queda INACCESIBLE, y el navegador NO deja saltarselo.

 >>> Pega por bloques. La consola web se come el primer
     caracter de cada pegada; por eso van con `echo ok;`.

 >>> Hay CINCO puertas 🚦. Si una no da lo esperado, PARA y
     pasame la salida. No sigas al bloque siguiente.

# Apunta lo que salga. Es la vuelta atras: si algo se tuerce,

# Ahora se AMPLIA el certificado que ya existe. No se crea otro:
# el vhost nuevo usa la misma ruta /etc/letsencrypt/live/space-os.io/

# >>> Efecto secundario bueno: la renovacion pasa de
#     `--standalone` (que paraba nginx) a `--webroot`, que no.

# 🚦 PUERTA 3 — que el nombre nuevo esta DENTRO del certificado:

echo ok; certbot certificates | grep -E 'Certificate Name|Domains|Expiry'
