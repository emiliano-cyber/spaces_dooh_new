 QUE ES ESTO
   El estatus de la flota deja de exigir SSH y `node` a mano:
   pasa a verse en https://space-os.io/flota/ , y una instancia
   que deja de responder manda un correo sola.

 LO QUE **NO** HACE, para que nadie lo espere
   · No muestra ninguna cifra de negocio. Siete columnas y ni
     una mas: nombre, dominio, canal, version, estado, fecha,
     origen. Esta sostenido por dos pruebas que fijan las
     claves EXACTAS.
   · No tiene usuarios propios ni contraseñas: pregunta al
     PADRE quien eres. Un `logout` alli apaga esto tambien.
   · No entra nadie sin permiso `administracion:ver`.

 CUANTO CUESTA: nada. Un proceso de 128 MB y una entrada de
 cron. No toca ninguna base de datos.

# ############################################################
#  PASO 2 · EL SERVICIO DEL PANEL      🚦 PUERTA 2
# ############################################################
#  Las variables van en el mismo archivo que ya usa el receptor.
#
#  OJO CON EL FORMATO, y NO es como `instancia.env`: systemd lee
#  este archivo EL MISMO, sin pasar por un shell. Un valor con
#  espacios no ejecuta nada -- pero tampoco se entrecomilla
#  igual. Una variable por linea, `CLAVE=valor`, sin `export`.

echo ok; cat >> /etc/space-os/flota.env <<'ENV'
URL_PADRE=http://127.0.0.1:3000
DIR_ESTADO=/var/www/Spaces/apps/flota/estado
AVISOS_PARA=CAMBIAME@tu-dominio
RESEND_API_KEY=CAMBIAME
EMAIL_FROM=Space OS <avisos@CAMBIAME>
ENV
echo ok; nano /etc/space-os/flota.env
echo ok; chown root:flota /etc/space-os/flota.env && chmod 640 /etc/space-os/flota.env

#  --- La unidad se COPIA, no se enlaza. Medido el 02/09 con
#      `spaces-demo`: systemd trata una unidad enlazada como
#      *linked*, y `systemctl disable` RETIRA EL ENLACE -- borra
#      la unidad en vez de apagarla, y la vuelta atras escrita
#      en cualquier tarjeta deja de funcionar.

echo ok; cp /var/www/Spaces/infra/systemd/flota-panel.service /etc/systemd/system/
echo ok; systemctl daemon-reload && systemctl enable --now flota-panel
echo ok; systemctl status flota-panel --no-pager | head -12

# 🚦 PUERTA 2 — `active (running)`. Y que conteste por loopback:

echo ok; curl -s -o /dev/null -w 'sin cookie -> %{http_code}\n' http://127.0.0.1:3002/

echo ok; cat /var/www/Spaces/apps/flota/estado/vigilancia.json

#  ESPERADO: un objeto `nombre -> estado` por cada instancia.
#  Ese archivo es la memoria del vigilante: es lo que hace que
#  no repita el aviso en cada pasada.

#  --- Y ahora el cron. Cada 10 minutos:

echo ok; cat > /etc/cron.d/flota-vigilante <<'CRON'
SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin
*/10 * * * * flota cd /var/www/Spaces/apps/flota && set -a && . /etc/space-os/flota.env && set +a && node vigilar.mjs >> /var/log/space-os/flota-vigilante.log 2>&1
CRON
echo ok; chmod 644 /etc/cron.d/flota-vigilante && mkdir -p /var/log/space-os && chown flota /var/log/space-os/flota-vigilante.log 2>/dev/null; touch /var/log/space-os/flota-vigilante.log; chown flota /var/log/space-os/flota-vigilante.log

#  ⚠️ ESA LINEA **SI** PASA POR UN SHELL (`. /etc/space-os/
#  flota.env`), a diferencia de systemd. Si `EMAIL_FROM` lleva
#  espacios --y los lleva, «Space OS <...>»-- TIENE que ir
#  entrecomillado en el archivo, o bash ejecuta la segunda
#  palabra. Es el defecto del 02/09 con `instancia.env`.
#
#  Comprueba que se lee bien ANTES de esperar 10 minutos:

echo ok; bash -c 'set -a; . /etc/space-os/flota.env; set +a; echo "[$AVISOS_PARA] [$EMAIL_FROM]"'

#  ESPERADO: los dos valores enteros entre corchetes. Si el
#  segundo sale cortado o aparece un error de «comando no
#  encontrado», faltan las comillas.

# 🚦 PUERTA 4 — dentro de 10 minutos:

echo ok; tail -5 /var/log/space-os/flota-vigilante.log
