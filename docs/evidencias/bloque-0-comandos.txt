 BLOQUE 0 - la tira de comandos, para copiar y pegar
============================================================
 Autoridad: docs/evidencias/captura-f3-f4.md
 Esto es SOLO la tira de comandos. El porque de cada uno, lo
 esperado y donde se pega la salida estan alli.
------------------------------------------------------------

 >>>  PEGA UNA LINEA CADA VEZ.                          <<<
 >>>  NO PEGUES EL ARCHIVO ENTERO NI VARIAS LINEAS.     <<<

 La consola web de DigitalOcean CORROMPE las pegadas de varias
 lineas. Paso dos veces en este proyecto (21/08 y 24/08): se
 comio caracteres, junto comandos y dejo la terminal esperando
 en ">". Una linea, enter, leer la salida, siguiente linea.

 Las lineas que empiezan con # son notas. NO se pegan.
============================================================


# ------------------------------------------------------------
# C0 y C3 - ESTAS TRES VAN DESDE TU MAQUINA, NO DEL DROPLET
# Son consultas a DNS publico. No hacen falta en el servidor,
# y en un droplet recien montado puede que ni exista `dig`.
# ------------------------------------------------------------

dig +short NS space-os.io

dig +short A space-os.io

dig +short demo.space-os.io

# Esperado C0 (las dos primeras):
#   - servidores de nombres terminados en  .ns.cloudflare.com
#   - el A del apice VACIO  (no tiene registro, y es lo normal)
#
# Esperado C3 (la tercera):
#   - demo.space-os.io -> 209.97.146.136
#
# >>> Si los NS NO son de Cloudflare: PARA y pasame la salida.
#     El plugin dns-cloudflare no podria escribir el TXT del
#     desafio y todo el bloque del certificado cambia.
#
# >>> EN WINDOWS `dig` NO EXISTE. Comprobado el 24/08.
#     Usa el archivo hermano:  bloque-0-dns-windows.txt
#     Trae las mismas tres consultas en PowerShell y en nslookup,
#     y explica por que la segunda parece un error cuando sale bien.


# ------------------------------------------------------------
# C1 - EN EL DROPLET - a que maquina estoy entrando
# Si entras por la consola web de DigitalOcean ya estas dentro:
# pega solo la linea de abajo.
# ------------------------------------------------------------

hostname; curl -s ifconfig.me; echo

# Esperado: la IP tiene que ser  137.184.107.53
#
# >>> Si sale otra IP: PARA. El 24/08 se censo entera la maquina
#     equivocada y se detecto tarde.
#
# Si prefieres entrar por ssh desde tu maquina, la linea es:
#   ssh -o ConnectTimeout=8 root@137.184.107.53 "hostname; curl -s ifconfig.me; echo"


# ------------------------------------------------------------
# C2 - EN EL DROPLET - GATE - la rama y el numero de migraciones
# ------------------------------------------------------------

cd /var/www/Spaces && git rev-parse --abbrev-ref HEAD && git pull && ls db/migrations/*.sql | wc -l

# Esperado:  feat/servidor-padre-instancias   y   72
#
# >>> Si sale `main`, o si el contador da 66: PARA.
#     En main faltan 6 migraciones, entre ellas la 72, que es el
#     arreglo de H1. DEMO naceria con tablas que otro rol crea
#     sin permisos Y SIN ERROR, con el pull saliendo en verde.
#
#     La salida, tambien en UNA sola linea:
#
#   cd /var/www/Spaces && git fetch --all && git checkout feat/servidor-padre-instancias && git pull && ls db/migrations/*.sql | wc -l
#
# >>> Si el `git pull` pide usuario y contrasena: PARA y pasame
#     lo que sale. Significa que el remoto del droplet es HTTPS
#     sin credenciales guardadas, y eso se resuelve aparte.
