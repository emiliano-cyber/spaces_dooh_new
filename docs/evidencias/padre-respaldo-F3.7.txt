============================================================
 QUE CIERRA, Y POR QUE IMPORTA
============================================================
 `update.sh` ya hace un `pg_dump` antes de migrar y lo deja en
 el disco de la instancia. Sirve para la vuelta atras de un
 release malo, que es su trabajo, pero NO SIRVE PARA NADA si el
 droplet desaparece -- y ese escenario es MAS probable con el
 modelo de instancias, no menos: son muchos droplets pequenos
 en vez de uno cuidado.

 Un respaldo que vive solo en la maquina que puede morir es un
 respaldo de mentira.

 LO QUE FALTA: el codigo esta escrito y probado en local, pero
 con `s3cmd` y `aws` FALSOS -- `pruebas-update.sh` los sustituye
 por binarios de mentira. Nunca ha ocurrido una subida real.

============================================================
 LA DECISION QUE SE APLAZA, PARA QUE NO SORPRENDA DESPUES
============================================================
 El plan pide «una llave por instancia con permiso solo sobre
 SU prefijo». **Eso no se puede hacer con Spaces**: sus llaves
 se limitan POR BUCKET, no por prefijo.

 Decidido el 27/08: se arranca con UN BUCKET COMPARTIDO y
 prefijos por instancia. Hoy hay una sola instancia, asi que esa
 propiedad no protege de nada todavia.

 DISPARADOR: se decide ANTES de dar de alta el primer owner
 (F5.7). La salida conocida es un bucket por instancia -- ahi
 una llave con alcance de bucket SI es una llave por instancia.

 1. Spaces Object Storage -> Create a Spaces Bucket
      Nombre  : space-os-respaldos
      Region  : NYC3
      CDN     : NO. Es almacenamiento privado, no contenido
                publico. Un CDN delante de tus respaldos es lo
                contrario de lo que quieres.
      File Listing: **Restrict File Listing** (privado)

 2. En el bucket -> Settings -> Lifecycle Rules -> Add Rule
      Prefix               : (vacio, aplica a todo)
      Delete objects after : 30 days

    >>> ESTO NO ES OPCIONAL, Y ES DELIBERADO QUE VIVA AQUI.
        `respaldo.sh` NO borra NADA en el bucket, a proposito:
        un `rm` mal escrito en un script que corre en TODAS las
        instancias es una forma elegante de perderlo todo a la
        vez. La retencion remota la hace el bucket, la revisa
        una persona, y no viaja en cada release.
        Sin esta regla el bucket crece para siempre.

 3. Spaces Object Storage -> Access Keys -> Create Access Key
      Alcance : limitado a `space-os-respaldos`
      Permiso : Read/Write
      Nombre  : padre-respaldos

    >>> Copia la clave y el secreto AHORA: el secreto se
        muestra UNA sola vez.
    >>> NO me los pegues. No los necesito y no deben pasar por
        esta conversacion. Van directos al archivo del paso C2.

 Cuando termines, pasame SOLO: el nombre del bucket, la region,
 y que la regla de 30 dias quedo creada.

# E1 [PADRE] - Un respaldo real de la base del padre.

#              no arriesga datos de nadie.

BK=/var/lib/space-os/respaldos; mkdir -p $BK; sudo -u postgres pg_dump -d spaces_prod -Fc -f $BK/spaces_$(date +%Y%m%d_%H%M%S).dump; ls -lh $BK/

# Esperado: un .dump con tamano > 0.
#
# >>> Si sale de 0 bytes, PARA. Un dump fallido se ve casi igual
#     que uno bueno, y subir un respaldo vacio es peor que no
#     subir ninguno: parece que hay respaldo.

# E2 [PADRE] - Subirlo.

set -a; . /etc/space-os/instancia.env; set +a; bash /var/www/Spaces/infra/scripts/respaldo.sh subir $(ls -t /var/lib/space-os/respaldos/*.dump | head -1)

# Esperado: lineas de `s3cmd put` con el progreso, y ninguna de
# error.

# E3 [PADRE] - EL CRITERIO DE ACEPTACION: esta fuera del droplet.

set -a; . /etc/space-os/instancia.env; set +a; s3cmd --access_key="$SPACES_KEY" --secret_key="$SPACES_SECRET" --host="$SPACES_REGION.digitaloceanspaces.com" --host-bucket="%(bucket)s.$SPACES_REGION.digitaloceanspaces.com" ls s3://space-os-respaldos/padre/ | tail -3

# Esperado: el archivo que acabas de subir, con su tamano.
#
# >>> Este comando SI pasa la llave por argv, y en el script NO

INSTANCIA=padre SPACES_BUCKET=space-os-respaldos bash /var/www/Spaces/infra/scripts/respaldo.sh subir $(ls -t /var/lib/space-os/respaldos/*.dump | head -1); echo "codigo: [$?]"
