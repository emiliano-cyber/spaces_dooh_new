 COMO FUNCIONA, EN CUATRO LINEAS (para saber que se esta encendiendo)
-------------------------------------------------------------------------------
  1. El boton lleva a una ruta NUESTRA, que responde 302 a Google. No hay
     JavaScript de Google en la pagina (Authorization Code + PKCE, decision 2).
  2. Al volver, el callback resuelve por `sub` (el id estable de Google).
  3. Si no hay vinculo, busca por el correo VERIFICADO y lo vincula solo. NO
     hace falta ninguna pantalla de vinculacion.
  4. Si ese correo no corresponde a ningun usuario, NO se crea nada: responde
     «no registrado». Google es un atajo de entrada, no un alta.

  O sea: para que alguien entre con Google, su usuario tiene que existir ANTES
  en Administracion, con el MISMO correo.

 PASO 2 — EL CLIENTE OAUTH EN GOOGLE CLOUD        (lo hace una persona)
===============================================================================
  Tipo: ID de cliente OAuth 2.0 → Aplicacion web.

  URIs de redireccion autorizados — CON BARRA FINAL:

    https://demo.space-os.io/spaces-dooh/api/auth/google/callback/

  !! LA BARRA FINAL NO ES OPCIONAL !!  Google compara la URI CARACTER POR
  CARACTER contra la registrada y NO sigue redirecciones en el callback. Sin la
  barra, la app responde 308 y el acceso muere con un error opaco. Ya nos costo
  un redespliegue el mismo detalle con la ruta del logo.

  Origenes autorizados de JavaScript: NO HACEN FALTA. Ese campo es para los
  flujos que llaman a Google DESDE la pagina (One Tap), que el ADR descarto
  (alternativa B). Si la consola insiste, el valor correcto es el origen a
  secas, SIN ruta y SIN barra final:

    https://demo.space-os.io

  Ojo a la contradiccion, que se presta a error: el ORIGEN va sin barra; la
  REDIRECCION va con ella.

  Para probar en local, anadir tambien (Google admite http solo en localhost):
    http://localhost:3000
    http://localhost:3000/spaces-dooh/api/auth/google/callback/

  ADR decision 6: el proyecto de Google Cloud lo posee una CUENTA DE EMPRESA, no
  la personal de nadie — para que no se vaya con quien se vaya.

===============================================================================
 PASO 3 — ENCENDERLO EN EL SERVIDOR
===============================================================================
  En /var/www/Spaces/apps/web/.env.production:

    GOOGLE_CLIENT_ID=...
    GOOGLE_CLIENT_SECRET=...
    GOOGLE_REDIRECT_URI=https://demo.space-os.io/spaces-dooh/api/auth/google/callback/

  La tercera es opcional pero SE RECOMIENDA explicita: deducirla del request
  detras de nginx (protocolo, host, puerto) es justo donde se cuelan las
  diferencias que hacen que Google la rechace.

  Luego:
    pm2 reload spaces-web --update-env

  NO hace falta reconstruir. Las tres variables se leen EN TIEMPO DE PETICION
  (no llevan prefijo NEXT_PUBLIC_, asi que Next no las hornea en el build), y
  `/api/auth/metodos` es `force-dynamic` a proposito, justamente para esto.
  Ojo: eso NO vale para `NEXT_PUBLIC_RECUPERAR_PASSWORD` ni
  `NEXT_PUBLIC_AUTOREGISTRO`, que SI exigen reconstruir.

    [ ] La pantalla de acceso muestra el boton de Google.
    [ ] Entrar con una cuenta cuyo correo YA exista como usuario: entra y queda

    [ ] Entrar con una cuenta cuyo correo NO exista: debe decir que no esta dada

    [ ] El mismo usuario sigue pudiendo entrar con su CONTRASENA. Google es un

        quedarse fuera sin poder recuperar la cuenta, y hoy no hay correo
        saliente para restablecerla.

 SI ALGO SALE MAL
===============================================================================
  APAGARLO es inmediato y no necesita revertir nada:

    en .env.production →  GOOGLE_OAUTH=0
    pm2 reload spaces-web --update-env

  Eso corta el flujo entero (`googleHabilitado()` lo comprueba primero) sin
  tocar la base ni el codigo. Los vinculos ya creados se quedan, inertes, y
  todos los usuarios siguen entrando con su contrasena.

  LA BASE NO HACE FALTA REVERTIRLA: la tabla vacia no estorba a nadie. Si aun
  asi se quisiera:

    begin;
      drop function if exists auth_usuario_por_identidad(text, text);
      drop table if exists identidades_externas;
    commit;

  Ojo: eso BORRA los vinculos, y quien ya entrara solo con Google tendria que
  volver a vincularse (entrando una vez con su contrasena y repitiendo el flujo).
