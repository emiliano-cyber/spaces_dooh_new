# Diario — 2026-10-14

## El release de `v0.11.9` falló: registro lleno

El run `38516330947` (`release.yml`, etiqueta `v0.11.9`, `20e928ea`) subió
todas las capas y al final DigitalOcean respondió **`denied: quota exceeded`**.
Es lo mismo del 02/10 con `v0.9.2` ([[01-Arquitectura/entorno-y-despliegue]]):
`registryspaces` está en el plan gratuito (500 MiB, unas 9 versiones
completas). **`v0.11.9` no quedó publicada**: ninguna instancia la puede tomar
hasta que se relance.

El remedio, que hace el dueño en el panel de DO:

1. Borrar etiquetas viejas de `space-os`, sin tocar `estable`, `beta`,
   `v0.11.8` ni la versión que tenga instalada cada instancia (su vuelta atrás).
2. **Garbage collection** del registro. Sin ese paso no se libera nada:
   borrar etiquetas solo deja las capas sin referencia.
3. `gh run rerun 38516330947 --repo emiliano-cyber/spaces_dooh_new --failed`

**Resuelto el mismo día:** el dueño limpió el registro y el relanzamiento del
run `38516330947` terminó **en verde** a las 13:37 UTC (9 min 34 s): `v0.11.9`
queda en `beta`, lista para promover a `estable` con `version = v0.11.9`.

**Y promovida a `estable`** por el dueño a las 13:59 UTC (run `38576580857`,
en verde, 20 s): `v0.11.9` y `beta` coincidían en `sha256:3f5d15ea…`, el smoke
en DEMO dio `login 200 · metodos 200`, y tras reetiquetar `estable` apunta a
**ese mismo digest**. La vuelta atrás es el `estable` anterior,
`sha256:2207b6cd…`. Lo que el run **no** comprueba es qué versión corre DEMO
(sin `/api/version` con token, F6.1).

Esto va a seguir pasando cada ~9 versiones mientras el plan sea el gratuito.
Las dos salidas, la limpieza automática en `release.yml` (borra imágenes del
registro de producción) o el plan Basic (gasto), **las decide el dueño**.
